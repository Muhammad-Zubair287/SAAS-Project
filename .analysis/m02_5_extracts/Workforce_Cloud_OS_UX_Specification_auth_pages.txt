2. UX Product Vision
The experience must make workforce operations feel like one connected system rather than a collection
of separate HR, attendance and payroll tools.
A user should be able to move naturally through the following connected lifecycle:
Employee created → onboarding completed → shift assigned → attendance recorded →
leave managed → payroll calculated → payslip published → reports updated.
The interface must provide a different experience for each role while using a shared design language
and data model.
3. UX Objectives
UX-001: Reduce Operational Complexity
Users should complete common workforce actions with the fewest practical steps.
UX-002: Make Status Visible
Every request, calculation, approval and process must clearly display its current status.
UX-003: Prevent Errors Before Submission
The interface should validate data early and explain how to resolve an issue.
UX-004: Support High-Frequency Mobile Usage
Employee attendance, leave, requests, notifications and payslips must be practical on mobile screens.
UX-005: Protect Sensitive Information
Payroll, banking, identification and private employee data must only appear to authorised users.
UX-006: Support Different Organisational Models
Navigation and workflows must adapt to tenant modules, permissions, departments, locations and
policies.

29. Responsive Behaviour
29.1 Desktop to Tablet
Sidebar collapses.
Multi-column cards reduce to two columns.
Filters move into a drawer .
Table columns reduce according to priority.
Secondary actions move into overflow menus.
29.2 Tablet to Mobile
Tables become record cards.
Multi-step forms become one section per step.
Right drawers become full-screen pages.
Sticky bottom action bars should be used for primary actions.
Summary information appears before detailed sections.
Charts simplify and provide accessible data tables.
29.3 Mobile Attendance
The attendance action must remain visible without scrolling on common mobile screens.
29.4 Mobile Payroll
Full payroll administration is not expected to be optimised for small mobile screens. Mobile payroll
users may view summary and approve where security policy allows, but calculation and complex
exception handling should direct users to desktop or tablet.
30. Urdu and Right-to-Left UX Requirements
The design system must support:
English and Urdu text expansion.
Right-to-left page layout.
Mirrored navigation.
Correct icon direction.
Urdu-compatible typography.
Mixed Urdu and English numbers.
Dates and payroll values that remain readable.
Form labels above inputs on mobile.
Avoidance of fixed-width text containers.
Localised error messages.
Language selection at login and within profile settings.
Business terms should use an approved terminology glossary to avoid inconsistent translations.
